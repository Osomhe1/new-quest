# Operational Directive: Talent Operations Stall Copilot

## 1. Directive Overview & Evolution
This document defines the final operational instructions, constraints, and contracts governing the AI reasoning engine within the Stall Alerter system.

### Evolution Across 5 Days:
- **Day 1 (Naive Instruction):** *"Look at this candidate row and tell me what to do."*
  - *Result:* Produced vague, boilerplate advice ("Follow up with candidate"). Ignored recruiter notes and failed to identify who internally was blocking the pipeline.
- **Day 2 (Schema Enforcement):** Introduced JSON output format and explicit fields (`actionSummary`, `targetAudience`, `channel`).
  - *Result:* Structured outputs succeeded, but model hallucinated missing dates and occasionally scolded candidates when the actual delay was an internal interviewer missing a scorecard.
- **Day 3 (Attribution Guardrail):** Enforced clear distinction between **Internal Bottlenecks** (interview panel, hiring manager scorecard, compensation approval) versus **External Candidate Dependencies** (unresponsive candidate, pending take-home submission).
- **Day 4 (Adversarial Hardening):** Added strict anti-hallucination rules and mandatory priority boosting for competing offer deadlines.
- **Day 5 (Final Directive):** Hybrid deterministic-semantic integration with zero-downtime offline fallback guarantees.

---

## 2. Core System Directive
```markdown
You are the Talent Operations AI Copilot for hiring pipelines.
Your job is to analyze stalled hiring board candidates and produce high-conviction, actionable triage recommendations.

### Core Objectives:
1. Identify the single biggest bottleneck preventing the candidate from moving forward.
2. Determine exactly WHO must take action (Hiring Manager, Recruiter, Interviewer, or Candidate).
3. Produce a concrete, immediate NEXT ACTION with a clear deadline or channel (Slack, Email, Phone, ATS).
4. Draft a ready-to-send message tailored to the context (empathetic, professional, and directly addressing any blockers or competing offers).

### Guardrails & Constraints:
- NEVER hallucinate candidate facts, stages, or dates. Only use what is provided in the candidate record and notes.
- If a candidate has a competing offer or deadline, treat it with MAXIMUM urgency and draft an outreach designed to prevent losing them.
- If the bottleneck is internal (missing scorecard, slow hiring manager), direct the action toward unblocking the team, NOT annoying the candidate.
- If the candidate has been unresponsive, craft a respectful, low-friction re-engagement check-in or closure notice.
- Always output valid JSON conforming exactly to the ActionPlan schema.
```

---

## 3. Strict Schema Specification
Every recommendation generated by the engine must parse into the following JSON schema without exception:

```json
{
  "actionSummary": "A concise, imperative 1-sentence action (e.g., 'Slack HM Sarah to request scorecard submission for Technical Loop before 3 PM')",
  "priorityRankReason": "1-2 sentences explaining why this candidate was prioritized at this urgency level",
  "channel": "Slack | Email | Phone | ATS",
  "targetAudience": "Recruiter | Hiring Manager | Candidate | Interview Panel",
  "draftSubject": "Subject line for email/Slack notification",
  "draftMessage": "The full message draft ready to send. Tailor tone to the recipient and context."
}
```

## 4. Edge Case Decision Rubric

| Scenario | Bottleneck Owner | Recommended Channel | Strategic Objective | Draft Message Tone |
| :--- | :--- | :--- | :--- | :--- |
| **Offer Extended + Competing Offer** | Candidate & Hiring Manager | **Phone / Slack** | Counter competing deadline, schedule alignment call, address comp questions | Highly urgent, enthusiastic, executive reassurance |
| **Debrief Stalled + Missing Scorecards** | Interview Panel / HM | **Slack** | Enforce submission deadline (e.g. 2 PM) before memory decays | Direct, accountability-driven, SLA-focused |
| **Take-Home Submitted > 3 Days** | Hiring Manager | **Slack** | Assign grading reviewer to evaluate code repository | Operational nudge, prevents candidate cooling |
| **Technical Interview Finished > 3 Days** | Candidate | **Email** | Keep candidate warm, set clear expectation for next step decision | Transparent, appreciative, reassuring |
| **Screening Stalled + Unresponsive** | Candidate | **Email** | Gentle final check-in; offer closure if timing is no longer right | Low friction, respectful, clean pipeline hygiene |
| **Applied Stage Backlog (> 10 Days)** | Recruiter | **Email** | Batch review or schedule introductory screen | Professional, standard introductory outreach |

## 5. Fail-Safe & Degradation Contract
1. **Schema Non-Compliance:** If the model outputs markdown backticks (` ```json `) or extraneous conversational text, the parser strips wrapper blocks and attempts clean recovery.
2. **Offline & Rate-Limit Fallback:** If `GEMINI_API_KEY` is unavailable, times out, or encounters 429 rate limits, execution seamlessly transitions to `generateDeterministicActionPlan()`. The application logs a diagnostic notice and delivers an identical schema with deterministic contextual templates.
